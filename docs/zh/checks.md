# 检查项：AI 写代码会怎么腐蚀仓库

[← 返回 README](../../README.zh-CN.md) · [English](../checks.md)

先说清楚：AI 不是故意把仓库写烂。它每次只盯着眼前这个需求，而且产出速度远快于人阅读。于是会出现这些很具体的现象：

| 你看到的现象 | 后面真正发生的事 | 拦它的检查 | 默认行为 |
| --- | --- | --- | --- |
| 项目明明有 `dayjs`，新代码又 `import moment` | 同一个能力出现两套工具，包体积、时区行为、升级节奏都分裂 | `deps` | 报错并直接给出正确库、封装文件路径和示例 |
| 已有封装好的 `http`，AI 直接 `import axios` | 鉴权、重试、埋点被绕过，线上问题难排查 | `deps` | 报错，指向 `src/services/http.ts` |
| 装了个新包，没人知道为什么装 | 依赖只增不减，半年后没人敢删 | `deps` | `package.json` 新增依赖没登记用途就失败 |
| 已经有一个 `UserCard`，AI 又写了一个差不多的 | 两份实现各自演化，改一处漏一处 | `ui` | 同名报错；props 高度重合告警 |
| 一个文件从 200 行涨到 800 行 | 没人能完整读懂，改动风险指数上升 | `metrics` | 超过配置行数就失败 |
| 复制粘贴一段逻辑到新文件 | 改 bug 要改两处，第二处总会忘 | `metrics` | 跨文件重复 token 块超比例就失败 |
| 到处 `any` 让报错消失 | 类型检查形同虚设，后面的改动全裸奔 | `metrics` | `any` 数量超过配置就失败 |
| 一个 PR 改了 40 个文件、2000 行 | 评审只能扫一眼，所有质量问题从这里漏过去 | `diff-size` | 超过文件数/行数就失败，并给出拆分步骤 |

## 每项是怎么检测的

- **依赖守卫（`deps`）**：读源码里的 `import` / `export ... from` / `require` / 动态 `import()`，把包名和 `package.json` 对照（monorepo 会按最近的 package.json + 祖先 workspace 依赖合并判断）；再按配置里的「能力 → 唯一库」判断。`package.json` 的新增依赖只和 git base 比一次，不做每次全量扫描。
- **组件清单（`ui`）**：扫描 `.vue` / `.tsx` / `.jsx`，抽出组件名、props、emits，写到 `.fe-guard/ui-inventory.json`。同名时按目录分级：涉及 `src/components/` 共享目录报 `error`（共享组件被重造），只在各自 feature 目录重名报 `warn`（业务分区常见）；`index.*` 入口文件不参与同名判定。props 重合度高统一告警。
- **腐化指标（`metrics`）**：单文件行数、最长函数行数、`any` 数量、跨文件 token n-gram 重复率。重复检测只比较跨文件的窗口，`.vue` 只比较 `<script>`，默认跳过 locales/i18n。四项都走「值棘轮」：baseline 记的是**允许的最大值**，不是条数。
- **大 diff（`diff-size`）**：`git diff --numstat --relative` 统计项目根下的文件数和新增行数，超过阈值失败。项目根是 git 根的子目录时只统计项目内改动，兄弟目录（如 backend）不算。**它故意不进 baseline**——大 diff 是「这次的事件」，不是历史欠债；入账等于把闸门永久关掉。
- **ESLint / TypeScript / 架构边界**：分别执行项目自己的 `eslint`、`tsc`（Vue 项目自动 `vue-tsc`）、`depcruise`，只做编排和输出归一化，不重造规则。

## 为什么组件清单按需查询，而不是写进上下文

组件清单会随着项目越长越大。把它塞进 `AGENTS.md` 或每次对话的上下文，等于用常驻 token 换一个偶尔才用的信息，而且清单一更新就过期。

所以清单落盘，只通过 MCP 工具 `ui_lookup` 按需查：AI 写组件前查一次，返回最多 5 条摘要（名字、文件、前 8 个 props/emits），通常不到 300 字节。`AGENTS.md` 里只留一句「写组件前先 `ui_lookup`」。它保持独立工具，不塞进 `task_*` 状态机：查询不推进阶段、不写事件，返回体也更小。

## 这套工具天生抓不到什么（诚实版）

- **「该不该复用」是语义判断**。两个组件名字不同、props 拆得不一样，但业务上就是重复的，`ui` 抓不到；它只能抓同名和高重合 props。
- **复制后重排格式 / 调换语句顺序**。`metrics` 的重复检测基于 token 序列，换行、调序都会让它认为「不重复」；「复制后改名」可开启 `duplication.normalizeIdentifiers` 命中（默认关闭）。
- **动态依赖**。`require(someVariable)`、运行时拼出来的包名，静态解析看不到。
- **生成代码**。lock 文件、`dist/`、`*.min.js` 默认忽略；如果你们的代码生成器产物在 `src/` 下，需要自己加进 `diff-size.ignore` 或调高阈值。
- **单文件内部的小步大改**。`diff-size` 只看增删行数，把一个 500 行文件整体重写但只加 20 行，它不会报；`metrics` 的文件行数可能也不会变。
- **团队是否真的评审**。工具只能把「大 diff」变成失败，不能保证人认真看。这条是流程问题，不是检测问题。
